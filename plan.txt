codezip:

Goals:
    Modify an already-compiled binary to maximize the amount of free space
        - the semantics of the binary to be modified cannot change.
        - the overall footprint of the binary cannot change
          (function entry points and extents do not move; instructions within a function may; data is not appended.)
        - assume we just want to maximize the amount of completely unused space in the binary (contiguity does not matter)

Basic idea:
    Reduce code size through several passes, including:
        - unused function removal
        - a highly aggressive variant of function outlining
        - leaf node optimizations

Overview:
    1. Disassemble the binary and recover function-level information
        - Recover a list of function entry points, locations in the binary, and lengths.
        - This is just an export from some arbitrary reverse-engineering tool - define a common format and expect it as input
        
    2. Uplift each function into a series of instructions
        - Extract code flow and dependency graphs
    
    3. Apply optimization passes
        - Mark unreferenced functions for removal
        - Remove redundant instructions
        - Apply function outlining
    
    4. Test the modified binary
        - Ensure the modifications did not break anything
        - Run a large C project's own test suite before and after


Overall project structure:

codezip.py:
    - orchestrator
    - takes arguments, invokes functions in other parts of project as necessary

input_parser.py:
    - Responsible for taking input from RE tool and converting to python object for later use
    - Should support: YAML and Ghidra XML files

parsers/yaml.py:
    - does yaml parsing to extract function info from YAML files

parsers/ghidra_xml.py:
    - does XML parsing to extract function info from XML files.

uplifter.py:
    - Responsible for turning function locations into instruction sequences and control-flow graphs
    - Splits ISA-specific details of this into isa/[isa].py 

ir.md:
    - data model and ISA encoding contract shared by the uplifter, optimizers, and ISAs

isa/isa.py:
    - superclass that ISAs should implement

isa/x86_64/:
    - The first ISA to be implemented
    - reuses Ghidra's x86-64 SLEIGH specification for disassembly and IR
    - other reasonable ISAs after

optimizers/function_remover.py:
    - Eliminates unreferenced functions

optimizers/outliner.py:
    - orchestrates the function outlining optimization.

binary/binary.py:
    superclass defining all the functions needed to interface with the binary file we're patching.

binary/elf.py
    - does the parsing necessary for ELF files

binary/pe.py
    - does the parsing necessary for PE files

binary/raw.py
    - does the parsing necessary for raw binaries

uplifter.py:

    class Uplifter:
    
        function_map = map [entrypoint -> Function]
        isa = ISA

        function __init__(string isa, Binary binary):
            create and store an ISA as appropriate
            save binary


        function uplift_function(Function f):
            
            list[Instruction] instructions

            - First, do a linear pass
            - Read function bytes out of src file
            - Starting at the first byte in the function, going to the end:
                instr = isa.disassemble(current location)
                instructions.append(instr)
                current location += instr.length
            
            - Next, do a code flow recovery pass
            - (isa.disassemble is only responsible for filling in flows_to)

            - Start at the first instruction and do a simple dfs/bfs on the flows_to list in order to fill in flows_from
                
                - for addresses that fall outside the bounds of the function:
                    - don't add them to the dfs list
                    - instead, add them to the outgoing_references list
                    - this includes UNK_NONLOCAL and UNK_LOCAL addresses
                

            - Now recover basic blocks
                - a basic block is a maximal straight-line sequence of instructions
                  ending at a branch or return; calls do not end a block
                - build the CFG by recursive descent from function entries and known targets
                - an outline window is a single-entry, single-exit straight-line region;
                  it is not the same thing as a basic block

            - reject the function if decoding fails, an instruction crosses the
              declared end, a flow target is not an instruction boundary, or
              decoded bytes are unreachable from the entry

            - exception: if a reachable instruction has an UNK_LOCAL flow, the
              remaining decoded bytes are treated as additional entry regions
              instead of being rejected.  The function keeps its UNK_LOCAL
              outgoing reference so CFG-dependent passes can skip it

            - add f to the function map
        
        function build_xrefs():
            - called only after all functions have been uplifted.
            - want to find all function calls.
                However, we can't rely on the incoming function list being complete
                    it may just be a subset of the actual functions in the binary
                    (Ghidra, for example, often misses functions called indirectly)
                So we do a linear disassembly on the full binary
            
            For each offset in the binary:
                
                isa.try_interpret_as_pointer(offset)
                    if that points to any of the function_map functions, add a ref from this offset to the function.
                    in the function's incoming_references list
                
                isa.disassemble(offset)
                    if that succeeds, check each of the flows_to addresses. If any of them map to a function,
                    add a ref from here to there in that function's incoming_references list.
                

    Model:
        Function, BasicBlock, Instruction, Address, StateSpace, Reference, and
        FreeSpace are defined in ir.md.
        BasicBlock owns instructions; Function owns basic blocks.


optimizers/function_remover.py:
    
    function run_optimizer(Binary, Uplifter, isa):

        for each function in Uplifter.function_map:
            if function has no incoming_references:
                remove the function from the function map
                add the space occupied by the function to the FreeSpace list
    
        return a list of free spaces


optimizers/outliner.py:
    - orchestrates the function outlining optimization.
    - Compilers frequently inline functions. This increases speed at the cost of code size.
        - What if we could undo that?
    - 'source sites' refers to the locations where instructions are being replaced
    - 'target site' refers to the location where the newly extracted bytes are stored.
    - must run after function remover
    - does not update unwind info yet; unwinding through an outlined block is out of scope

    instruction_map map[position_invariant_instruction_encoding -> set[BasicBlock]]

            where position_invariant_instruction_encoding is just the bytes of the function re-linked to a standard address

    function run_optimizer(Binary, Uplifter, isa, free_space):
        extract_instruction_regions(Binary, Uplifter, isa)

        if we weren't able to successfully extract anything, return

        relink_in_instructions(extracted_instructions, extracted_basic_blocks, free_space)

    function extract_instruction_regions(Binary, Uplifter, isa):

        if the isa doesn't support function outlining:
            note a warning and return

        for each function in Uplifter.function_map:
            if the function has_unk_local_reference:
                continue
            if isa.uses_red_zone(function):
                continue
            for each basic_block in function:
                for each instruction in that basic block:
                    add the basic block to the set of that instruction in instruction_map
    
        Now find the best matches for each basic block.

        extracted_instructions = list[BasicBlock]
        basic_blocks_to_regenerate = list[(BasicBlock original, BasicBlock modified)]

        For each function:
            if the function has_unk_local_reference:
                continue
            for each basic_block in function:
                if this basic block has already been outlined:
                    continue



                profitable_matches = find_basic_block_matches(basic_block)

                for matching_basic_block in profitable_matches:
                    if try_generate_replacement_bytes(*matching_basic_block) succeeds:
                        
                        - mark all the containing basic blocks as used for outlining
                        - add the extracted instructions block to extracted_instructions
                        - add all of the modifications to basic_blocks_to_regenerate
                
        if extracted_instructions or basic_blocks_to_regenerate are empty:
            return failure
        
        Now we need to reassemble all the functions we extracted data from.

        from each of the basic_blocks_to_regenerate:
            get the containing function, and if it still needs to be regenerated:

            first, iterate through the function's instructions, keeping track of the current base address.
            For each, call isa.relocate_instruction(instruction, new_base_address)

            Next, work back through the list a second time to make branch targets work.
            For each branch, keep track of the instruction it used to target and call
            isa.set_instruction_target(branch, new_location_of_that_instruction)

            Functions must not grow. If relocating a branch would exceed its encoding range,
            reject this candidate and leave the function unchanged.

            If an instruction has >2 possible local targets, then the UNK_NONLOCAL flag should have been set -> so this should all work out ok.

            finally, add the freed data between the new end of the function and the old end of the function to a list.

        return success, with: the free space list, the list of instructions that still need to be linked, and the set of extracted basic block regions that we still need to stitch in to the binary


    function relink_in_instructions(extracted_instructions, extracted_basic_blocks, free_space):


        for each basic block we need to link back in to the binary:
            add a return instruction at the end, if some other step has not already done so.
            find the smallest free space that can hold this basic block.
            
            put the instruction list in the binary at that location.
                this involves relinking each instruction to be at the new base address.
                Then, call isa.add_extra_stack_space to handle the modified stack pointer 
            
            remove the used space from the free_space list
            for all the instructions that should point to that basic block:
                call isa.set_instruction_target(instruction, the location)



    function find_basic_block_matches(block) -> list[tuple(set(basic_block), set(common_instructions))]
        Find the set of basic blocks this block could be combined with that would save the most bytes overall.
        
        There are two criteria for the number of bytes a combination would save:
            - the length of the encoding of the instructions in common
            - the number of basic blocks with those common instructions
        
        But the combination of those two will depend on the ISA.
            - ultimately at each source site, we're going to need to inject a call instruction
            - then at the target site we're going to need to do the common instructions, then return

        Get: number of bytes for the call instruction and number of bytes for the ret instruction from the ISA.

        So the overall number of bytes saved if a particular combination works is:
            ((combined instruction length - call instruction length) * number of sources)
                - combined instruction length - ret instruction length

        The combined instruction length is subtracted once more because the
        shared block itself has to be stored in free space.  A match that does
        not pay for its own target block is not profitable.

        bb_match = map from basic_block -> int best_matches

        for each instruction in this basic block:
            if isa.is_outlinable(instruction):
                add 1 to each basic block in instruction_map[instruction]

        reduced_bb_match = throw away all basic blocks where the savings formula above is <= 0.
            also require common instruction length >= call instruction length.

        Now from those matching basic blocks we extract the combination that saves the most bytes.

        Use a map again:
            - hash function on the set of matching instructions

        matching_instruction_map = map[set(instructions)] to set[basic_blocks]
        so for each basic block in reduced_bb_match:
            union the set of this_bb instruction and that_bb instructions
            matching_instruction_map[result].add(that_bb)
            may as well add this_bb as well for good measure.
        
        Now calculate the profitability of each entry in matching_instruction_map
        return a sorted list of the 10 most profitable


    function try_generate_replacement_bytes(basic_blocks, common_instructions):
        We're given a set of basic blocks that have some number of instructions in common
        We need to try to shift each basic block around such that we can actually outline those common instructions.

        To do that, we need some kind of dependency graph.

        1. Resolve instruction order

        The common instructions need to appear in the same order in all basic blocks.
        That isn't guaranteed to be the case; we need to determine if it is, and if not if we can make that so.

        For simplicity, assume the final instruction order is one of the instruction orders that appears in the incoming basic blocks

        TODO: can we make this an arbitrary order, not just one of the incoming orders? Seems like a SAT problem. (Don't solve this yet.)

        for each src_basic_block in basic_blocks:

            reordered_blocks = list[BasicBlock] initialized_with src_basic_block

            source_indices = find_indices(src_basic_block, common_instructions)
        
            ordered_instructions = get instruction order from source_indices

            for other_basic_block in basic_blocks that aren't src_basic_block:
                this_order = find_indices
                reordered_block, start_offset = convert_basic_block_to_given_instruction_order_and_minimize_instruction_distance()

                if reordered_block is None:
                    fail this src_basic_block ordering and try the next one
                
                reordered_blocks.append((reordered_block, start_offset))
            
            if we couldn't make this src reordering work:
                continue to the next one
            

            convert_basic_block_to_given_instruction_order_and_minimize_instruction_distance guarantees the instructions will end up in the same order.
            It also guarantees that all those instructions are adjacent.


            Now we just need to extract all those segments from each basic block.

            create a basic block that's just the extracted instructions

            for each reordered_block in reordered_blocks:
                replace the instruction sequence with a special instruction of type outline_result_call
                give that instruction a reference to the extracted_instruction basic block

            return success with all the reordered basic blocks and the extracted basic block.

        if we couldn't find a reordering, return fail.


    
    function find_indices(basic_block, instructions_to_find):
        return list[indices of instructions_to_find in basic_block.instructions]

    
    function convert_basic_block_to_given_instruction_order_and_minimize_instruction_distance(basic_block, instructions_to_move, target_instruction_order):

        for moved_instruction in target_instruction_order[1:]:

            target_location = 1 position in the basic block after the previous instruction in target_instruction_order
            moved_instruction_group = list[instruction] init'd with moved_instruction

            iterations = 0
            while the position of the moved_instruction_group doesn't start at the target_location:
                iterations += 1
                if iterations > len(basic_block.instructions):
                    return failure


                see if we can swap the moved_instruction_group with the instruction nearer the target location
                

                if we can:
                    do the swap and record the modified list[instruction] in the basic block. Make sure to keep all instruction fields in sync.
                
                if we can't:
                    if the instruction we're trying to swap with is in target_instruction_order:
                        return failure
                    otherwise, add that instruction to the moved_instruction_group in the right location. (start or end depending on move direction)


            the instruction is now at the correct relative location in the basic block, with the minimum number of non-target instructions between it and the previous target instruction.

            try to swap all of the non-target instructions in moved_instruction_group to the other side of the instruction chain
            (such that all the target instructions are adjacent)
            if we can't:
                return failure

        
        if we were able to move all instructions to the right location, return success. Also return the offset into the basic block that the target instructions start at.

    
    function can_swap_instruction(list[instruction] group_to_move, instruction to_swap_with):

        we're allowed to swap the group with that instruction if:
            - the group doesn't depend on any of to_swap_with outputs
            - to_swap_with doesn't depend on any of group_to_move outputs
        
        calculate that based on the instruction fields:
        list[StateSpace] modifies
        list[StateSpace] depends_on

        This is legal because we're treating all locations with persistent side effects as registers.

        TODO: If the target ISA requires software-enforced delay slots, this model may be unsound.

binary/binary.py:

    class Binary:

        function open:
            reads the data

        function read:
            takes a (virtual) address and length and returns the data there

        function write:
            takes a (virtual) address and data and patches the in-memory image
            (never the file on disk)

        function virtual_to_file:
            maps a virtual address to a file offset

        function write_to_disk:
            takes a filename, does any required metadata fixups, then writes
            the in-memory image
                - rewrite or remove unwind info (.eh_frame / .pdata) for modified functions
                - rewrite relocations that point into moved code
                - update symbol sizes
                - TODO: exact formats per binary type
